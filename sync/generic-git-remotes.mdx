Reflect's guided GitHub flow handles the most common case, but the sync engine works with any git remote you can reach over SSH. GitLab, Gitea, Codeberg, GitHub Enterprise, your own server, or a bare repository on a NAS — wire the remote yourself and Reflect adopts it automatically.

**The contract: if `ssh -T git@host` works in your terminal, sync works.**

Reflect authenticates SSH remotes through your existing `ssh-agent`. It never asks for, stores, or manages credentials for non-GitHub hosts. The managed GitHub token is scoped to `github.com` and is never sent anywhere else. HTTPS remotes for non-GitHub hosts are not yet supported — use the SSH URL form.

## Basic setup

<Steps>
  <Step title="Initialize the repository">
    ```bash
    cd /path/to/your/graph
    git init -b main                                     # skip if it's already a repo
    git remote add origin git@gitlab.com:you/notes.git  # any SSH remote URL
    ```
  </Step>
  <Step title="Confirm authentication and record the host key">
    ```bash
    ssh -T git@gitlab.com
    ```
    This confirms your key is accepted and writes the host's public key to `~/.ssh/known_hosts`. Reflect will refuse to connect to a host that isn't already trusted.
  </Step>
  <Step title="Open or refocus the graph in Reflect">
    Reflect detects the remote when the graph folder is opened or when the app window regains focus. **Settings → Backup** shows the remote URL. From this point, edits back up automatically a few moments after you stop typing, and pulls/merges run on every launch and focus.
  </Step>
</Steps>

## NAS or local bare repository

A bare repository on another disk needs no credentials at all:

```bash
git init --bare /Volumes/NAS/notes.git
cd /path/to/your/graph && git remote add origin /Volumes/NAS/notes.git
```

Open or refocus the graph — Reflect adopts the local path as its remote exactly like a networked one.

## Restoring on another machine

```bash
git clone git@gitlab.com:you/notes.git ~/notes
```

Open `~/notes` as a graph in Reflect. The search index rebuilds from your Markdown files, and the remote is adopted automatically — no extra configuration needed.

## When sync fails

Failures surface in **Settings → Backup** (and as a dot in the sidebar). Reflect retries on the next focus event — sync never wedges permanently.

<Tabs>
  <Tab title="SSH agent offered no key">
    ```bash
    ssh-add ~/.ssh/your_key        # load your key into the agent
    ssh -T git@<host>              # confirm it's accepted
    ```
    Then refocus Reflect to trigger a retry.
  </Tab>
  <Tab title="Unknown host key">
    Reflect never bypasses host-key verification.

    ```bash
    ssh git@<host>                 # accept the host key interactively
    ```

    This writes the key to `~/.ssh/known_hosts`. Refocus Reflect afterwards.
  </Tab>
  <Tab title="HTTPS remote">
    HTTPS remotes for non-GitHub hosts require a stored credential (username and token in the OS keychain). Until one exists, Reflect refuses adoption and shows the advice inline. The simplest fix is to switch the remote to its SSH URL:

    ```bash
    git remote set-url origin git@host:owner/repo.git
    ```
  </Tab>
</Tabs>

<Warning>
  Reflect **never** bypasses host-key verification. Run `ssh <host>` at least once from your terminal to accept the key and record it in `~/.ssh/known_hosts` before expecting Reflect to connect. A key that isn't in `known_hosts` will cause every sync attempt to fail.
</Warning>

## Repository visibility is your responsibility

The guided GitHub flow creates a **private** repository by default. For a hand-wired remote, Reflect has no API to check repository visibility — there is no way for the app to know whether your GitLab project, Gitea instance, or self-hosted server is public or private.

**Notes marked `private: true` are included in the backup.** The `private` flag controls which external services can read a note's content — it is not a backup exclusion filter. Use your git host's access controls (private repositories, deploy keys, branch protection) to protect the backup.

## Stopping backup

Go to **Settings → Backup → Stop backing up**. This drops the `origin` remote from the local repository — your git history stays on disk. To reconnect, run the same `git remote add origin …` command you started with and refocus Reflect.
